# Agent Note: 技能卫生纪律与简化勘探证据链

Status: proposed

## Problem

技能目录生长后出现两类失真：一是模型可见的工具定义改动散在正文，
触发条件藏进深层、同一事实在定义与提示节互抄，上下文越改越大；
二是删除类提案只凭符号零命中立论，动态消费者与扩展点未被举证，
历史成功案例被当成删除清单复用。

## Proposal

在技能契约下新增两条纪律，只约束新增与改写，不追溯既有技能：

- 工具定义卫生：最小上下文优先；延迟加载资源全部可检索；
 关键约束前置到动作前；输出有界，给标识或路径而非全文倾倒；
 每事实只说一次；有条件者记录（模型名 + 提示版本 + 输入 token 数），
 无条件者诚实标注未测（判据体以 spec-ponygo-v2.5 rev2 §3.3 为准）。
- 简化勘探证据链：删除或收窄类提案给出生产者到可观察结果的全路径、
 失去的能力清单、最强保留理由；符号零命中不等于可删；
 历史案例只作提问清单。

方法论设计模式侧追加同源两条原则句，细则只留技能契约一家。

## Alternatives considered

- **全量返工既有技能**：否决。无真实消费者驱动，违反三次法则豁免理由。
- **只收卫生、不收证据链**：否决。两类失真同属技能生长期的对称问题，
 分开收会留半边。
- **写成 L2 硬门禁**：否决。两条均为语义判断，只能靠 review。

## Acceptance criteria

- `.agents/skills/README.md` 新增纪律 4/5，节首写清只约束新增与改写；
- `docs/methodology.md` §3.3 追加同源原则句，§7.1 增补证据链四件套与计数不选优；
- `tests/run.sh` 新增静态存在性断言；CLI 零改动。

## Risks

- 纪律被读成追溯返工：节首约束句对冲。
- 证据链被当成固定模板：保留理由与提问清单属性需 review 守住。

> 实证出处注：卫生纪律源自 deepseek-harness 的 `agent-experience` 技能
> （最小上下文 / 发现显式化 / 约束前置 / 有界输出 / 每事实一次）；
> 证据链源自其 process 类 2026-09-19 简化勘探决策
> （producer→outcome 全路径 / 失去能力清单 / 最强保留理由 / 计数不选优）；
> ponygo 侧只收通用纪律句，不收其 token 量测与试验计数。
