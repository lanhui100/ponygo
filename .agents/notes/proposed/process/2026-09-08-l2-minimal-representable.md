# Agent Note: 让"最轻的 L2"在判据里可表示（§5 与 §6 的矛盾修复提案）

Status: proposed

## Problem

`maturity-ladder.md` §6 的停止线表对"单人 + 决策密度 ≥ 1 条/周"建议「保留 L1 + 上最轻的 L2
（仅 format 门禁，不上 classification / 冻结 / 文档分层）」；但 §5 的 L2 判据是 2.1–2.5 全项，
其中 2.5 = 文档分层已激活，而 `ponygo` 在 `level >= 2` 时把 2.1–2.5 全部当硬判据
（`ponygo` 的 `verify_ladder`：`if [ "$lv" -ge 2 ]`）。

结果：**照 §6 行事的单实例，`ponygo status` 会判它 FAIL**——它永远无法声明 L2。§6 承诺的
中间态在 §5 里不可表示。两份独立审核（TASK-002）各自独立发现了这条矛盾，并因此反对把
ponygo 自身升到 L2。

## Proposal

把 2.5 从无条件判据改为**条件判据**：

- 仅当实例显式声明启用文档分层（`meta.yaml` 增加合法键 `docs-tier: on`，或
  `.meta/docs-tier/` 下存在显式标记文件）时，才校验 2.5；
- 未声明时**跳过**并在输出里如实标注 `2.5 SKIPPED（实例未启用文档分层）`——不计入 PASS，
  也不判 FAIL；
- 配套修 `maturity-ladder.md` §6：把"最轻的 L2"定义写死为「2.1–2.4 + `docs-tier: off`」，
  §5 增补"条件判据"的语义与诚实标注要求。

## Alternatives considered

- **保持现状（L2 必须全项），把 §6 的"最轻 L2"删掉、改为"停在 L1"**：可行且最小改动，
  但丢掉"只上 format 门禁"这个真实存在的中间态，等于用删建议来消解矛盾。
- **把 2.5 降级为 WARN**：文档分层会完全失去机械看守，与 v2.0「文档治理前置到 L0/L1」的
  决定直接冲突。
- **整体重写 §6 阈值表**：范围过大；阈值来自 dsh 实证，无新证据前不动。

## Acceptance criteria

- `ponygo` 在 `docs-tier: off`（或未声明）时跳过 2.5，输出含 `2.5 SKIPPED`，且**不**并入
  "全部 PASS"的结论行；
- `docs-tier: on` 且未激活时 2.5 仍 FAIL；
- `tests/run.sh` 覆盖上述两个分支；
- `maturity-ladder.md` §5 与 §6 两处口径一致，并被场景 29 式的口径断言覆盖。

## Risks

- **声明即豁免**：实例不声明 `docs-tier` 就绕过 2.5。缓解：SKIPPED 必须出现在输出与结论行里，
  且 `audit` 的门禁分层报告仍会提示文档分层缺失。
- **与 v2.0 决定的张力**：文档治理前置是 v2.0 的核心决定，条件化可能被读成回退——
  需一次 review 确认优先级后再实施。
- **`meta.yaml` 加键**：该文件的铁律是"只留一个真值源字段"，新增 `docs-tier` 键需同时
  说明它为何不是冗余副本（它是实例的**启用声明**，不是可从目录推导的事实——目录存在不等于
  已激活）。
