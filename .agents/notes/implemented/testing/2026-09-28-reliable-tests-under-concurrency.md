# Agent Note: 并发下测试可靠性的三条通用原则

Status: implemented

## Problem

测试在单跑时全绿、并行或在 CI 上偶发红，是多语言、多栈项目的常见失效类。
既有审计细目只问"有没有门禁/钩子/CI/负样本"，不问测试自身的隔离与等待语义：
共享资源先探后占、固定 sleep 当就绪证据、清理只发取消不等完成，都会产生
与产品无关的偶发失败，进而诱使加超时、加重试、全串行、吞错、弱断言等掩盖式修法。

## Decision

三条栈无关原则已收为审计问②机制层附录号判据 2.A–2.C（形状 + review，不做跨栈语义门禁；
2.7/2.8 激活时顺延编号、本附录号不重编）：

- **2.A 资源隔离**：并行测试的共享资源（端口、套接字、固定路径、外部命名空间、
 全局可变状态）由资源所有者的原子分配器获取，禁止先探后占；
- **2.B 就绪与完成等待**：断言等待被测方拥有的可观测就绪或完成信号，
 超时只做等待上界、不做正确性条件，固定 sleep 不得充当证据；
- **2.C 处置到静默**：清理在获取后立即注册，关闭或取消后等到子进程退出、
 服务关闭或等价完成信号，才算收尾完成。

配套七类诊断分类（F1 宿主资源碰撞 / F2 生命周期不完整 / F3 进程全局污染 /
F4 负载敏感同步 / F5 平台或入口差异 / F6 产品并发缺陷 / F7 外部依赖瞬态）
与分流三问（隔离后显式 overlap 仍现 → F6；换 OS/shell/入口消失 → F5；
串行消失 → F3/F4）、复现阶梯（单测进程起逐级升到首个复现签名），
原则 + 分类表唯一家为 `docs/methodology.md` §4.7；`gates/README.md` 只留一链入行
（本行非门禁、无执行语义）；checklist 判据链到该节。

## Alternatives considered

- **进 L2 硬门禁**：否决。跨栈语义不可机械判定，小项目会因此产生摩擦，
 违反停止线。
- **维持现状（只查门禁存在性）**：否决。门禁存在性证明不了测试自身可靠，
 偶发失败会持续消耗信任。
- **逐栈写死命令**：否决。ponygo 是通用框架，判据必须栈无关，
 栈示例只作 review 起点。

## Consequences

- checklist 问②新增 2.A–2.C（`audit/checklist.md`），用法小结计数同步 15→18
 （`depth-selector.md` / `README.md` / `tests/run.sh` s18 原子同改）；
- 原则 + 分类表唯一家为 methodology §4.7；gates 一链入行；scorecard 问②补
 "2.A–2.C 任一有 review 记录 / 分类表可指到 methodology §4.7" 校准句；
- `tests/run.sh` 新增 s32 静态断言（全称锚定 + file:line 回显）；
- `ponygo` CLI 六命令面零改动（heredoc 模板同步五条纪律 + 链入行）；
- review 程序被读成机械门禁的风险 → 每条判据行内标注"靠 review"、
  gates 链入行声明"本行非门禁、无执行语义"；
- 诊断分类被当成故障归因终点的风险 → 分类只定位举证方向，不替代复现证据。

> 实证出处注：通用原则源自 deepseek-harness 的 `dsh-ci-test-reliability` 技能
> （资源原子分配 / 就绪-完成等待 / 处置到静默 / 七类 flake 诊断与复现阶梯）
> 与 testing 类 2026-09-08 前后决策记录；ponygo 侧只收栈无关形状与 review 程序，
> 不收任何 runner、框架、脚本专名。
