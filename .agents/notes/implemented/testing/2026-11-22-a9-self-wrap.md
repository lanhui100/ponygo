# Agent Note: A9 补自包裹（零残留 spec 的挂死从「job 超时」变成「95s 内点名」）

Status: implemented

## Problem

`.meta/gates/no-residue.spec.sh`（门禁资产 A9）是唯一**没有** timeout 自包裹的出厂 spec
（backlog **B025**）。A2/A7/scratch-hygiene/backlog 四个 spec 都有
`GT=${PONYGO_GATE_SPEC_TIMEOUT:-90}` + `exec timeout -k 5`，A9 一个都没有。

这条缺口是 `2026-11-18-spec-default-timeout` 的**已知残留**：那次把四个 spec 的默认上限从 30s 提到 90s 时，
记录里明确写了「A9 没有自包裹 → 本批不动」，并把风险列在 Consequences 里。B025 随后把它落账。

后果不是「慢」，而是**故障不可归因**：A9 用两条检索路径（`rg --no-ignore --hidden` / 退化 `grep -rIlF`）
遍历隐藏目录与被忽略目录。若某平台上其中一条挂死（正则/编码/符号链接环导致的等待），
A9 不会像其它 spec 那样在 ~95s 内打印 `FAIL` 并退出，
而是拖到 CI job 级 `timeout-minutes` 才被判死——日志里只剩「整个 job 超时」，
与 A9 无关的用例（尤其同 job 内后续场景）一并被埋，事后无法从日志判断「是不是 A9 的问题」。
门禁的失败必须自己说出来，不能靠外层 job 的代价替它发声。

## Decision

1. A9 补上**与 A2/A7 逐字同款**的自包裹（8 行）：
   - `GT=${PONYGO_GATE_SPEC_TIMEOUT:-90}`（未设默认 90s，KILL 兜底 `-k 5`）；
   - 格式门：`*[!0-9]*|0*` → stderr `FAIL` + `exit 2`；
   - 上界门：`${#GT}` 五位且 `>86400` → stderr `FAIL` + `exit 2`（GNU `timeout` 会接受超长整数并视为
     「不设上限」，而预算行照打——假护栏）；
   - 双闸 + 可用性探测：`PONYGO_SPEC_SELFRUN != 1 && PONYGO_SPEC_NO_GUARD != 1 && command -v timeout`
     才 `export PONYGO_SPEC_SELFRUN=1; exec timeout -k 5 "$GT" bash "$0" "$@"`。
   - **spec 内零平台判定**：平台真值仍只存在于 `ponygo` 一处（契约 C13）。
2. A9 新增**自身形状断言**：spec 读自己的源码，断言自包裹的两个必需片段在场
   （`PONYGO_GATE_SPEC_TIMEOUT` 与 `exec timeout`）。防的不是今天——是未来某次编辑把这段删掉而无人察觉。
   「门自己不响」这件事，只有让门自己检查自己的形状才拦得住。
3. **双写同步**：A9 在 `UPGRADE_UNIVERSE` 内，`ponygo` 用自己的 heredoc 播种到消费仓。
   磁盘文件与 `ponygo` 内嵌副本**同批**修改，并逐字节比对（EOL 归一后 `identical=True`），
   否则 `ponygo init/upgrade` 播种出的 A9 仍是旧版。

## Alternatives considered

- **用固定 `timeout 90` 常量，不读 `PONYGO_GATE_SPEC_TIMEOUT`**：否决——B024 已经证明「固定常量」
  会在 Windows 慢平台上把慢误判成挂死（A2 曾被自己的 30s 默认值杀掉）。自包裹的意义就是
  「跟随平台预算」，写死等于把平台判定偷偷搬回 spec 内部。
- **在 A9 内复制 `is_windows()` 做平台分档**：否决——契约 C13 明确「平台真值只允许存在于 `ponygo` 一处」；
  而且 B008 正在消灭的正是这类第二份真值，两条待办会互相抵消。
- **不补自包裹，改为在 CI 里给 A9 单独设更小 `timeout-minutes`**：否决——治症状不治机制。
  门禁资产的健壮性应由资产自己持有，不能依赖每个消费仓的 CI 配置记得为它加护栏。
- **只加自包裹，不加形状断言**：否决——自包裹是「可被后来者无声删掉」的一段代码。
  A9 的职责就是「证明 no-residue 门会拒非法样本」；它连自己有没有护栏都不检查，
  等于把「未来是否被削弱」交给 review 的注意力。
- **判定为平凡改动（「加 8 行包装」）不写记录**：否决——它改变了 A9 的**失败语义**
  （从「不可归因的 job 超时」变成「`GT+5s` 内点名 + 配置类错误 `exit 2`」），
  属于改门禁判据面，命中「非平凡」判定表。
- **等下一个 spec 相关批次一起改**：否决——B025 已经存在 4 天（2026-11-18 落账），
  且 A9 缺护栏的风险随每次 CI 拓扑调整单调上升；8 行机械改动没有理由继续挂账。

## Consequences

- A9 现在可归因：`PONYGO_GATE_SPEC_TIMEOUT=abc|0|99999` → `exit 2`；合法值 → `exit 0`；真挂死 → `~GT+5s` 内 124。
- 本仓 A9 实跑收据：`bash .meta/gates/no-residue.spec.sh` → `exit 0`，
  `##SPEC asserts=34 rejects=11`。
- A9 的自检输出行数从原有断言基数 +N（新增形状断言），
  若消费仓有「A9 输出断言数」的硬编码锚需同批更新（本仓无此锚）。
- 相关但**未在本次解决**：AT2 夹具重复实现平台真值（B008，`2026-11-18-spec-default-timeout` 的 Risks
  提到的另一条）。两者同源（第二份实现），但分属不同发布面（门资产面 vs 验收夹具面），
  故拆条记录、分开提交。
