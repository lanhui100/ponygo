# Agent Note: A8 两条检索路径同口径（rg 加 --no-ignore）与「不造空清单仪式」的裁决

Status: implemented

## Problem

审计的两条 P2（`docs/dev-team/reviews/2026-11-17-qms-implant-effect-audit.md` §3 U9/U10）：

1. **平台口径分裂 = 更松的一侧假放行**：A8（`no-residue.sh`）的 rg 分支默认尊重 `.gitignore`，
   grep 退化分支不尊重——同一棵树在"装了 rg"与"没装 rg"（Windows Git Bash 常见）下判决相反。
   文件头注当时写「被 ignore 的文件在退化路径下仍会被检索（更严，不放宽）」，但**rg 侧才是更松的那侧**：
   删掉的符号若只在 build 产物目录（被 ignore）里残留，装 rg 的机器会判"零残留"。
2. **框架仓的 A8 恒空转**：本仓无 `.meta/gates/no-residue.manifest`，门永远「跳过（清单不存在）」并 exit 0，
   每天在 CI 跑却从未判定过任何东西。

## Decision

1. **rg 分支加 `--no-ignore`**（保留 `--hidden`/`--no-messages`/`--fixed-strings`/`-l`）：两条路径的检索面
   一致 = 当前树全部文件（含被 `.gitignore`/`.ignore` 忽略者），都只排除 `.git/`。头注与
   `.meta/gates/README.md` 的"已知边界"改成同口径表述，删除"rg 更严"的说法。
   A9 负样本新增"忽略目录内的残留，两条路径都必须拒"用例（正控制：删掉残留后两条都放行）。
2. **框架仓不造空清单（把 U9 判为"不做")**：
   - 空清单不会让门判定更多东西——清单里没有真名字时，判定面仍是零；补一份空清单只是为了让门
     "看起来在跑"，属仪式而非验证（P8：没有捍卫者的不变量不是架构）。
   - 框架仓当前**没有**可登记的已删符号族：历史上移除的 `ponygo repair`／`--yes`／`PONYGO_IN_SPEC`
     等字面量仍出现在文档与 ADR 正文里，登记即自命中——为让门通过而先删掉文档里的证据，
     才是真正的假门禁。
   - 取而代之：在 `.meta/gates/README.md` 的 A8 行与门头注写明"骨架不播种清单；清单是删除发生时
     由人登记的判定项，**空清单不构成验证**"，让"跳过"这句话可被正确解读。
   - 不改退出码、不加新状态、不在框架仓创建清单文件。

## Alternatives considered

- **把"清单缺失"改成 fail-closed（缺清单即 exit 1）**：否决——它会把每个未发生删除的实例都逼去造空清单，
  用仪式换绿；而且这条门唯一起作用的时机正是"发生了删除"，缺清单本身不构成风险。
- **在 rg 分支禁用 ignore 规则之外，再反向让 grep 也尊重 ignore（改成同样松）**：否决——"两边一样松"
  等于统一放弃对 build 产物/生成物的检查，与命约 3「搜索零残留」的目的相反。
- **用 `--no-ignore-vcs` 而非 `--no-ignore`**：否决——`--no-ignore-vcs` 只无视 VCS ignore，仍尊重
  `.ignore`/`.rgignore`；本门要的是"检索面 = 当前树全部文件"，必须 `--no-ignore`。
- **在框架仓造一份"历史已删符号"清单**：否决——那些字面量仍在文档/ADR 里，登记即自命中；若为此改写
  历史文档，等于删除证据（P9 负空间的反面）。
- **给 A8 汇报"空转"次数并做看板**：本批否决——没有消费者（唯一消费者是人读 CI 日志），
  留到真的出现"删除后忘登记"事故再说（YAGNI）。

## Consequences

- 装了 rg 与没装 rg 的机器现在给出同一判决；真残留藏进被 ignore 的产物目录也逃不掉了。
- 代价（诚实登记）：两路径都要扫 build 产物/依赖目录，大仓扫描更慢；A8 本就不是高频门（删除时跑一次），
  可接受。
- 框架仓的 A8 仍恒跳过——这是**已裁决的设计事实**，不是缺口；未来若本仓真的删除了一批符号，
  登记一次清单即让它开始判定。
