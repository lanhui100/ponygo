# Agent Note: 双语配对记录的分节键格式

Status: implemented

## Problem

整文件哈希的配对记录有一个结构性冲突：同一配对的两个分支改了不同节，
记录行依然冲突，合并工具在远端检查侧也不会运行本地合并驱动，
导致纯记录冲突阻塞合并。生成区与代码块的再生也会反复弄脏记录，
而它们本就是双语逐字节一致、无需翻译的内容。

## Decision

方法论 §2.8 已改为双格式说明，首句为"**旧整文件哈希记录仍有效，已落盘实例无需迁移。**"：
旧格式段保留有效性声明 + 判据 1.9 口径不变；新分节键格式为推荐（新双语实例采用），
判据体以 spec-ponygo-v2.5 rev2 §3.2 为准：

- 记录键取标题 slug 路径（任取一侧为键侧，不假设英文存在；CJK 保留原文去空格，
 去空格后重名同 `~2` 规则，靠 review）；首个标题前内容键为 `/`（仅作首节键，
 与路径根同形但不作文件系统根）；同级重名依次 `~2`/`~3`；
- 每节存两侧哈希，算法由实例自选；代码块与生成区（实例自认并旁注定义）不入哈希；
- 条目排布以相邻节变更落不同文本块为目标（启发式，非保证）；验证见合并实例；
- 未声明双语的实例零影响；已落盘旧记录无需迁移。

## Alternatives considered

- **强制迁移旧记录**：否决。迁移收益只归双语实例，强制全量迁移违反停止线。
- **新增配对格式门禁**：否决。ponygo 尚无配对门禁实现，空门禁是死重。
- **维持整文件哈希唯一口径**：否决。结构性冲突会随双语实例增多而放大。

## Consequences

- `docs/methodology.md` §2.8 双格式并存，首句写死旧格式仍有效；
- `tests/run.sh` s32-I 断言分节键标题 + 旧格式有效原句 + `~2`/同级重名规则；
- 未声明双语实例的 status 与 audit 输出与实施前一致（status 输出 diff 实测：
  L1 判定/骨架/级自洽不变，仅决策数 15→18 为新增 ADR 的预期变化）；
- 被读成强制迁移的风险 → 首句有效性声明 + 零影响条款对冲；
- 键规则被实现成机械门禁的风险 → 键规则只作推荐形状，正确性靠 review。

> 其 merge 回放量级见该记录 §Measured effect）；ponygo 侧只收键规则形状与
> 双格式说明，不收其记录文件格式、脚本名与量测数字。
