# Agent Note: 临时产物分家与退场标准（scratch / 证据 / 决策）

Status: implemented

## Problem

中间产物（临时脚本、验证截图、执行日志、评审 JSON、阶段性 plan）在本仓此前**没有统一标准，也没有退场判据**：

- 它们散落在 `.dev-team/`（604K），且排除规则依赖 `.git/info/exclude` 的单机隐式配置——
  **本机生效、不入库、不可传递**。换机器/新克隆/CI 均不可见，存在误提交巨量日志的隐患。
- 过程产物体量已显著膨胀：`.dev-team/` 占已跟踪语料的 44%，且随每次开发轮次线性递增。
- **证据与垃圾同构**：验收要求物理凭证（机器 Exit Code、测试日志或截图），但多次重试产生大量无效副产物。“留什么、删什么”缺乏客观判据，导致默认堆积。

框架虽然内部有代码级临时文件清理纪律（如 `mktemp` + `trap` 清理），但缺少**工作区资产维度的治理标准与门禁**。

## Decision

确立“用途定去向”的三级分家模型，显式化忽略策略并挂载轻量门禁守护：

### 1. 三级分家原则

| 类别 | 判定标准 | 统一归属 | Git 追踪 | 退场与生命周期 |
|---|---|---|---|---|
| **决策 (Decisions)** | 为什么这样设计 | `.agents/notes/` | 跟踪入库 | 永久留存，状态机迁移 |
| **证据 (Receipts)** | 怎么证明满足验收 | `docs/dev-team/receipts/` | 跟踪入库（纯文本为主） | 随里程碑封印冻结 |
| **中间产物 (Scratch)** | 过程副产品，可再生产 | `.scratch/<yyyy-mm-dd>-<topic>/` | **强忽略（不入库）** | 关单即删 / TTL 7 天 |

### 2. `.scratch/` 契约（单一临时边界）

- **唯一出口**：所有临时脚本、抓包、调试日志、验证截图统一落在 `.scratch/<yyyy-mm-dd>-<topic>/`，禁止在项目根目录或源码子目录平铺。
- **目录即标签（TTL 编码）**：直接以 `yyyy-mm-dd` 日期作为目录前缀，由目录名自携带生命周期，严禁维护额外易漂移的 manifest 文件。
- **初始化创建契约**：`.scratch/` 作为工作区临时根目录在项目启动时一次性创建，内含只读契约说明 `README.md`，并在根目录 `.gitignore` 中声明版本化忽略规则；彻底移除 `.git/info/exclude` 中的隐式配置。
- **构建与发布物理隔离**：构建与发布输入严格采用白名单（基于 `git ls-files` 或显式目标文件），CI/构建流程绝不消费 `.scratch/` 下任何文件。

### 3. 证据蒸馏机制（先蒸馏，后销毁）

- **20 行文本原则**：删除 `.scratch/` 原始件前，将最终验证结果提炼为物理收据（命令 + Exit Code 0 + 关键标准输出 ≤ 20 行），持久化写入对应里程碑的验收文档。
- **截图控制**：无法文本化的视觉判断截图限制每次交付 ≤ 3 张且仅保留最终态；中间重试截图作为 Scratch 直接清理。

### 4. 退场机制与轻量门禁

- **双轨退场**：关单验收时主动清理对应的 `.scratch/<topic>/` 目录；超过 7 天的未清理目录由周期性命令兜底清理。
- **轻量门禁资产**：在 `.meta/gates/scratch-hygiene.sh` 落地门禁并在 `ci-verify.sh` 挂载，负样本由 `scratch-hygiene.spec.sh` 保障：
  - **E1**：`git ls-files` 严禁出现 `.scratch/` 路径（违例 exit 1）；
  - **E2**：`.gitignore` 必须显式声明 `.scratch/` 忽略（违例 exit 1）；
  - **E3**：构建及发布链路文件不得显式引用 scratch 目录（违例 exit 1）。

## Alternatives considered

- **A. 全量入库所有过程产物**：虽然具备审计能力，但会造成仓库体积极度膨胀（数十兆过程日志与截图），污染 Git 历史与 Release 产物 → 否决。
- **B. 继续依赖 `.git/info/exclude` 单机排除**：虽对已有环境零侵入，但规则无法在团队和 CI 间共享同步，存在严重一致性缺陷 → 否决。
- **C. 引入独立的 TTL 扫描守护进程或复杂调度**：引入不必要的机制税与后台依赖，违背零依赖与极简原则 → 否决，采用目录名编码 + 轻量门禁。
- **D. 针对文件体积/数量设置硬阻断门禁**：语义阈值极易误报大型性能诊断场景，违反 L2 阶段防过度治理原则 → 否决，仅做结构性合规阻断。

## Consequences

- 团队所有开发者与 AI 代理获得统一、可预期的临时文件工作区。
- `.gitignore` 显式接管忽略规则，多机一致，杜绝临时产物误提交。
- 形成“证据提炼-垃圾清理”的自然闭环，仓库体积保持健康受控。
