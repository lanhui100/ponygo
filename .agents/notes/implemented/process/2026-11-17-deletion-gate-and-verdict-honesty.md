# Agent Note: 删除决策记录入册（A1 扩 ACMRD）与 CLI 结论行诚实化（通过 → 已判定部分通过）

Status: implemented

## Problem

植入效果审计的两条 P1（`docs/dev-team/reviews/2026-11-17-qms-implant-effect-audit.md` §3 U3/U5）：

1. **删除决策记录不受任何门看守**：A1 的暂存区取值用 `--diff-filter=ACMR`（无 `D`），实测
   `git rm .agents/notes/implemented/process/x.md` 后 A1 exit 0「无暂存 ADR 变更」，A4 也绿。
   与常载命约 3「移除本身是一次决策」直接冲突——删掉一条决策记录比写一条省事得多，负空间
   （P9）要求删除有同等判据、同等验证、同等记录。
2. **结论行把"未判定"读成"通过"**：`ponygo status` 在只判了 1.1–1.9 的情况下打印
   `级自洽验证：通过（… 1.10 未由本命令验证——由 A1/A4 门把关）` 并 exit 0。按退出码消费 CLI 的
   脚本/agent 会把 1.10/1.11 违例读成绿灯——括注虽诚实，判词本身在制造虚假安全感。

## Decision

1. **A1 扩到 `ACMRD` + 删除须同提交入册**：暂存区存在被删除的 `.agents/notes/*.md` 时，同一次暂存
   必须包含 `.agents/notes/implemented/simplification/` 下的新增/修改文件，否则 `die`（exit 1）：
   `拒绝：删除决策记录（<path>）必须同提交入册 implemented/simplification/（含围栏外
   ## Reintroduction conditions 与检索收据）——移除本身是一次决策`。满足时把暂存文件照常交给
   判定真源 `verify-note.sh`，1.11 的形状判据不在 A1 里复制（P9 一份判据一份实现）。
   A2 新增三条负样本：删 ADR 无简化 note → 拒；有合法简化 note → 放行；简化 note 缺复活条件 → 拒。
   `archived/**` 的删除仍归 A6 封印门，不重复判定。
2. **CLI 判词诚实化（只改 L1/L2 通过行）**：`级自洽验证：通过（` → `级自洽验证：已判定部分通过（`。
   括注内容不变；**L0 纯长驻行不改**（L0 无 ADR 判据可判，不存在"部分"）；`未通过` / `未判定` /
   `跳过` 行不改；`status --json` / `audit --json` 的字段与 `exit` 值不改；退出码语义完全不变。
3. **测试随契约迁移**：`tests/` 下 15 处 `级自洽验证：通过` 断言迁到新判词（覆盖 6 个套件），
   `wave13/f4_coverage_honesty.sh` 的 `FROZEN_L1` / `FROZEN_L2_BASE` / COV-2 期望串与 NOGO 断言同步；
   COV-4 的 L0 逐字断言保持原样。

## 审核修正（2026-11-17 独立对抗审核，verdict=FAIL / 1 BLOCKING / 10 ADVISORY）

- **BLOCKING（生命周期迁移被误判成删除）**：`proposed → implemented` 的迁移若被 git 表示成 `D + A`
  （不用 `git mv`，或改写后相似度 <50%），会被判成"删除决策记录"而拒绝提交（重放真仓提交 `8edd7cf`
  即复现，而同一新文件单独跑真源是 0）。修法：删除项的 **basename 在同一次暂存里被新增 ADR 再次出现
  → 视为迁移**，不要求简化记录（新文件照常进 PATHS 由真源校验）；同时给 `git diff --cached` 加
  `--find-renames=50%`（默认阈值）兜 rename 表示法。
  **为何不是更激进的 1%**：实测 1% 会把"删除一条 ADR + 新增一条不相干 note"配对成重命名，
  真删除被整个掩盖——阈值越松，判据越容易被绕过。
- **ADVISORY 同批修**：入册载体必须是真决策记录（`simplification/README.md`、`AGENTS.md`、`*.zh.md`
  不能充当）；只删 `*.zh.md` 译文视为随母语版同批补齐、不要求入册（与 1.7/1.10/1.11 同口径）；
  简化 note 未提及被删路径时打一行「建议复核」WARN（语义关联不做硬判，P6）。
- **措辞修正**：`die` 文案不再笼统称"必须含检索收据"——准确口径是"复活条件必须有；写了
  `## Removed surface` 时还须一行 `rg`/`grep` 检索收据"；ADR 关于 `archived/` 的归属改写为
  "归档件的删除/移出由 A6 封印门承担（含 manifest 孤儿检测）；归档件与其 manifest 行被同时改写
  属 A6 已声明的 review 边界"。
- **残留风险（诚实登记）**：当"删除 A + 新增 B"被 git 判成 rename（相似度 ≥50%）时按迁移处理、
  不要求入册——真 mv 不是删除，这是有意设计；代价是"内容相近的大幅改写式删除+新增"可借此绕开入册判据。
  若未来要封死，方向是对 `--find-renames` 用更高阈值并只对"同 basename"认迁移（留下一批）。

## Alternatives considered

- **把 1.10/1.11 搬进 CLI 让 status 全判**：否决——`maturity-ladder.md` 已按 P9 明确拒绝"一份判据两份实现"，
  且只读命令执行仓库脚本（`verify-note.sh`）违反 `methodology.md` §4 的安全边界。
- **保留"通过"判词、另加一行 WARN**：否决——WARN 不计入 PASS 等于默认放过（1.10 决策时已立此论）。
- **删 ADR 一律拒绝**：否决——负空间要求删除是**可行且有验证**的工程（P9），一刀切禁删把语料腐烂变成
  永久债务。正确做法是要求"删得有理有据"（同提交简化 note + 复活条件）。
- **把删除判定放到 A4（全树门）**：否决——A4 没有暂存区信息，只能比对 git 历史，误报面大且与本地层重复；
  本地层是唯一知道"这次提交要删什么"的地方（P7 分层强制）。
- **给 A1 新增退出码区分"缺简化 note"**：否决——A3 钩子与既有消费者只理解 0/非零；加档位只增加契约面。
- **只改文档不改判词（说明「通过仅指 1.1–1.9」）**：否决——括注已经这么写了而审计仍判它误导；说明再多
  也改不了"通过"两个字在退出码消费者眼里的含义。

## Consequences

- 删一条决策记录现在需要同一提交里带一条 simplification note（1.11 会机械校验复活条件与检索收据）——
  删除的成本从"git rm 一行"回到"一次决策"。
- 判词变更会波及任何按字符串匹配 `级自洽验证：通过` 的下游（本仓 6 个套件已同批迁移）；实例侧若有
  自定义脚本匹配该串需自行更新——这是有意的可见变更，不提供兼容别名（不保留第二份判词）。
- 旧实例的 A1 要跑 `ponygo upgrade apply` 才带上删除判定（A1 是宇宙内资产，`upgrade --check` 会先报
  `stale`/`modified` 分类提示）。
- 实现边界（写死，防再议）：删除项**不进** `verify-note.sh` 的入参——暂存区已无字节，交给真源只会
  制造 TOCTOU 假红；A1 只判"同提交有没有入册"，被删记录的历史形状由 1.11 在同提交的简化 note 上判。
  `archived/**` 的删除/移出由 A6 封印门承担（含 manifest 孤儿检测——归档件的条目删了、manifest 行还在，
  A6 自己就会拒）；本判据只管**非 archived** 的删除。归档件与其 manifest 行被**同时**改写属 A6 已声明的
  review 边界（没有 git 历史真值可对，纯内容校验分辨不出来），不在本判据的兜底范围内。
- 残留风险（诚实登记）：A4 仍不知道"历史删除"，只在本地层拦；直接 `--no-verify` 或删钩子的绕过面
  由 B020 与 U7 承接。
