# Agent Note: 把 1.9b 判据搬进 verify-note.sh，让 A1/A4 统一看守 AI 常载面（已否决）

Status: rejected — 判定真源只能读单条 ADR 的文本，读不到 meta.yaml 开关状态与投影块成对性；搬进去必然造出第二份成对哨兵判据（P9 双实现漂移），且此后改投影形态要两处同改。

## Problem

1.9 的三个子项里，1.9b（根 `AGENTS.md` 存在且含 `docs/AGENTS.md` 字面链，条件于 `ai-surface: on`）
的看守面比另外两项窄：它只由 CLI 的 `verify_ladder` 判（`ponygo status` / `ponygo audit` 共用），
而 A1（pre-commit）与 A4（`ci-verify.sh`）经判定真源 `verify-note.sh`，只覆盖 1.1–1.8 与 1.9a。
后果是：一次提交可以带着「根 `AGENTS.md` 缺失」通过本地钩子，直到有人手跑 `status` 才发现——
`ai-surface: on` 是"声明即承诺"，而承诺的载体缺位却没有任何本地门拦。

容器化 CI 里还多一层绕行：检出不含 `core.hooksPath`（git config 不入库），A5 workflow 必须先
`git config core.hooksPath .githooks` 再跑 `audit --run-specs`，才借同一个 `verify_ladder` 覆盖到
1.9b。也就是说"CI 里 1.9b 一定被覆盖"依赖一条额外的步骤，而不是判据真源的天然覆盖面。

## Proposal

（将来时原文冻结；本条只是提案留痕，状态只写在 `Status:` 行，正文不改写成决定）

拟把 1.9b 的判定搬进判定真源 `verify-note.sh`，具体形态：

1. 真源新增跨文件读取：读 `.meta/meta.yaml` 的 `ai-surface` 值（`on` / `off` / 未声明三态）；
2. `on` 时检查根 `AGENTS.md`：存在、含 `docs/AGENTS.md` 字面链，且投影哨兵块
   `<!-- BEGIN constitution -->` … `<!-- END constitution -->` 恰成对（BEGIN 行号 < END、块内非空）；
3. 未声明 / `off` 时该子项 SKIPPED、不计入 PASS，并输出 WARN 催声明；
4. 真源头部「对齐契约」的判据范围由 1.1–1.10 扩为「1.1–1.10 + 1.9b」，使 A1/A4 的绿与 CLI 的绿
   在语义上等价；
5. `ponygo` 侧删掉自己那份 1.9b 分支，改为消费真源结论，避免双实现。

预期收益：任何提交（本地钩子 / CI）都拦得住"声明了 AI 常载面却没有常载入口"；判定面收敛到一处，
"报告绿、门禁红"的错位永久消失。

## Alternatives considered

（当时比较过的处置；采纳的那条见 `implemented/process/2026-11-09-adr-criteria-hardening.md`
的 Decision 第 3 条与 Alternatives 第 1 条）

- **A. 只在 CLI 侧判 1.9b，真源不动（最终采纳）**：保留真源"逐条 ADR 文本判据"的语义边界，接受
  A1/A4 看不到 1.9b；代价是本地 pre-commit 不拦、CI 只能靠 A5 的 `audit --run-specs` 步兜住。
  选它，是因为 1.9b 判的对象**不是一个 ADR 文件的格式**——它是 `meta.yaml` 开关 + 根投影块 +
  包目录扫描的组合，属于"实例状态"；塞进"逐条 ADR 校验"的脚本会把真源的语义边界打散。
- **B. 把 1.9 三个子项统统搬进真源**：否决。1.9c（包文档覆盖）要扫 `packages/` `crates/` `src/`
  三个包根并读 `.meta/docs-tier/exemptions` 白名单，与本方案同一个越界问题，只是更贵。
- **C. 让真源支持"插件式跨文件判据"（配置驱动的扩展点）**：否决。会引入第二套判据描述格式
  （等于新的 manifest / DSL），与本框架"一份判据一份实现、零依赖单文件"直接冲突；且跨文件判据的
  语义无法用同一套 `grep`/`awk` 口径表达，等于把判据真源变成一个小解释器。
