# checklists/audit.md —— 改造（对已有项目的治理体系体检与优化）

> 给**非 0 进度、已有治理痕迹（或已有散落的决策/门禁）**的项目。目标：体检 → 定位缺口 →
> 每个缺口落成一条「最小改进动作」，最终产出改造路线图。
>
> 铁律：**按"结果"评分，不按"工件形状"评分**——已用别的方式达成同等效果的，视为"已认可替代物"，不打成缺口；默认倾向不动已在工作的更轻机制。

---

## 四步法

### 第 1 步：定档

```bash
ponygo audit            # 自适应定 S/M 档（或 --level M 强制）
```

- 先读 `audit/depth-selector.md` 的 5 条探测命令，理解为什么定到这一档。
- **S 档也要查完骨架层全部项**；别用"我是小项目"当躲检借口。

### 第 2 步：打分

- 按 `audit/checklist.md` 逐项跑命令、勾选命中；`scorecard.md` 给四问各打 0–10。
- 记下**命中率 + 每问水位画像**。分量表判"维度在哪档"，细目库判"具体缺哪条"。

### 第 3 步：缺口 → 最小改进动作（按杠杆排序）

把 0 分项落成动作清单，**强制层优先**（它是其余三层的放大器）：

1. **强制层**（问②缺项）：挂本地钩子、加最小 CI——收益最高，先做。
2. **决策层**（问①缺项）：补决策载体 / 触发规则 / Alternatives。
3. **复用层**（问③缺项）：把高频流程资产化为 skill。
4. **退场层**（问④缺项）：建 archived + 冻结封印。

每个动作必须小到**一次提交可完成**；拒绝"先做整套治理体系"式大而空。

### 第 4 步：复查 + 终点判定

```bash
ponygo status           # 确认整改后级别是否上升、骨架是否完整
ponygo audit --level M  # 复查，确认命中数上升
```

**合法终点有三种，务必如实判定**：

| 终点 | 判定 | 动作 |
|---|---|---|
| **升格** | 缺口清晰、投入划算 | 执行第 3 步的最小动作 |
| **维持现状** | 现有机制已在工作、本框架不产生新收益 | **不做改动**，这是合法结论，不是偷懒 |
| **降级** | 机制过度、治理税 > 收益 | 移除/归档多余机制（P9 负空间：删除是独立工程，记录为一条 decision） |

## 防"负价值改造"的回归检查（写入前自问）

- [ ] 本项改造是否替换了一个**已在工作且更轻**的机制？→ 是，则不推荐（"已认可替代物"应予保留）。
- [ ] 本项补的工件，是否**不产生新收益、只为匹配框架形状**？→ 是，则标记为"仪式"，砍掉。
- [ ] 是否把一个本该"靠 review"的语义判断，误判成了可机械强制？→ 是，则回退到 P6 诚实标注。
- [ ] 改造后，团队是否要同时维护新体系 + 旧体系两套？→ 是，则先想清迁移，别并行重负。

一份「改造路线图」：现状等级 → 目标等级 → N 条按杠杆排序的最小改进动作 → 各自的验收命令。
写入 `.agents/notes/proposed/{class}/yyyy-mm-dd-audit-roadmap.md`（proposed 态），执行完再迁到 implemented。
