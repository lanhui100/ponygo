# 四问分量表（Scorecard）

> **给谁、何时用**：给 `ponygo audit` 的调用者（旧项目改造者或随时体检者）与审计器的实现者。在运行分层细目库（`checklist.md`）之前，先用这四问拿到一份**粗粒度、不依赖细目数量**的整体画像——它回答"这个项目的治理在四个维度上各自大概在哪个水位"，并给出对照标杆。它只判方向、不定档；定档交给 `depth-selector.md`，逐项打分交给 `checklist.md`。

---

评分纪律（全局约定，四问通用）：

- **先找磁盘证据，再打分。** 不看 README 自述、不看团队口头承诺。每问的结论必须能指到一个目录 / 一个文件 / 一条命令。
- **每问 0–10 分**（只取整数，判"有没有 / 对不对"，不判"深不深"——"深不深"是精微层的事，见 `checklist.md`）。
- **每个 0 分点 → 一条最小改进动作**（"最小"= 能在一个 PR 内落地的单点动作，非整套体系）。
- **缺口之间找杠杆**：强制层（问②）是其他三层的放大器，资源不足时优先投它。详见 `audit.md` 的杠杆排序。

---

## 问①　决策记在哪？（Decision Memory）

**一句定位**：这个项目里"为什么这样 / 为什么不那样"的决定，是落进了专门的、可被路径编码和门禁校验的载体，还是散落在人脑、聊天记录、PR 讨论里随人员流动蒸发？（P1 记忆瓶颈原理）

**看哪几个面**：

1. **有专门载体吗**：是否存在一个目录专门放决策记录（ADR / decisions / notes），而不是"README 里顺带提一句"。
2. **路径编码状态吗**：lifecycle（proposed / implemented / rejected / archived 四态）与 class（类别轴）是否编码进文件路径（文件夹即标签），还是靠文件内手写标签（会漂移）。
3. **状态与内容一致吗**：文件头 `Status:` 行是否与所在目录一致（三重锁定：路径 + 内容 + 门禁）。
4. **被否掉的选择留痕吗**：每条记录是否强制带 `## Alternatives considered`（候选方案与落选原因）；rejected 目录是否非空。
5. **覆盖面靠规则还是自觉**：触发条件是否**枚举化**（"命中任一即必须写"），还是靠一句"重要的要记"。

**对照标杆**（dsh 实证，摘自 `../docs/methodology.md` §2）：implemented 604 篇 / proposed 26 / rejected 10 / archived 169（均含中文配对）；强制 `Alternatives` 节；触发条件枚举化（§2.5「非平凡变更 = 命中任一」）；`rejected/` 非空且带一行拒绝理由（§2.4）。

**这问的打分刻度**（供审计器校准，不替代细目）：

| 水位 | 特征 |
|---|---|
| 0–2 | 无专门载体；决定散在聊天 / PR / 人脑 |
| 3–5 | 有载体，但路径无状态编码、无 Alternatives、覆盖面靠自觉 |
| 6–8 | 四态路径 + Status 头 + Alternatives 到位，仅触发条件未枚举化或 rejected 工具不足 |
| 9–10 | 全到位 + supersession 审计（同 PR 处理取代）+ 枚举化触发 |

## 问②　承诺怎么强制？（Enforcement）

**一句定位**：宪法 / 文档里的"必须 / 禁止"，有几条变成了**非零退出的命令**去拦截违例？（P2 可验证性原理：靠自觉的约定在规模与人员变化下必然衰减。）

**看哪几个面**：

1. **非零退出命令的密度**：约定数与"能 `exit 1` 拦截违例的门禁数"之比。凡机械可查的承诺没配命令 = 0 分点。
2. **单点还是分层**：是只在本地一个 hook（pre-commit），还是本地 + CI 分层（P7 分层强制原理：本地窄、CI 全）。
3. **门有没有负样本证明**：门禁有没有配套"构造非法样例证明门会拒绝"的 negative sample spec，还是"写了门但没人证明它能抓"。
4. **门本身有没有被管**：CI workflow 的形状是否被断言的（门也是代码，配置变更像任何变更一样要评审）。

**对照标杆**（dsh 实例，§4）：lefthook（L1 pre-commit 6 项）+ GitHub Actions（L3 CI 9 个聚合 job）+ `scripts/` 机械验证脚本家族，**每个门通常配一个负样本 spec**（§4.5），`ci-workflow.spec.ts` 把整个 CI 形状钉死（§4.6）。

**打分刻度**：

| 水位 | 特征 |
|---|---|
| 0–2 | 约定只在文档里，无一条可执行门禁 |
| 3–5 | 有 1–2 条本地 hook，无 CI、无负样本 |
| 6–8 | 本地 + CI 分层到位，缺负样本 spec 或 workflow 形状契约 |
| 9–10 | 分层门禁 + 每门负样本 + 门被门检验 |

## 问③　重复劳动怎么复用？（Reuse）

**一句定位**：高频 + 高判断力的流程，是口传、一次性交接文件，还是入库的**可复用资产**（skill）？（P3 载体分工原理：一次性判断 → note，当前事实 → doc，重复程序 → skill。）

**看哪几个面**：

1. **有没有 skill 资产**：是否存在专门目录放可复用流程（skills），而非每次现写 / 靠老员工口传。
2. **触发式 description 吗**：每个 skill 的 description 是否写"何时用"（路由条件内联），还是在正文里藏着触发条件（懒加载时看不到）。
3. **校准样例吗**：skill 是否带正反例成对的校准样例（把语义判断锚定到具体事实），还是没有样例的散文步骤。
4. **调用权限分层吗**：重型 / 危险流程是否 `disable-model-invocation`（只许用户点名），还是任何流程都可被任意路由。

**对照标杆**（dsh 实例，§3）：10 个技能，全带内联触发 + 证据面匹配；`dsh-translate-docs` 标 `disable-model-invocation: true`；校准样例刻意用"533 词归档、248 词保留"证明字数与结论无关（§3.2）。

**打分刻度**：

| 水位 | 特征 |
|---|---|
| 0–2 | 无 skill 资产；流程靠口传 / 一次性文档 |
| 3–5 | 有零散 skill，但 description 无触发、无校准样例 |
| 6–8 | trigger 内联 + 校准样例到位，仅调用权限分层缺失 |
| 9–10 | 全到位 + 证据面匹配（按改动表面选最小充分证据） |

## 问④　过时的怎么退场？（Retirement）

**一句定位**：超过一半的"退场"设计藏在归档里——这是多数项目最大的盲区。这套项目里，"该退休的决策 / 资产"有没有**冻结归档**机制，还是过期产物在工作区里无限堆积？

**看哪几个面**：

1. **归档机制存在吗**：是否有 archived 态 / 归档目录（区别于"删掉"或"永远留着"）。
2. **只有活件能归档吗**：归档判据是语义判断（决策已闭合、理由不再指导未来），还是靠字数 / 年龄一刀切。
3. **归档后冻结吗**：归档件是否哈希封印（append-only manifest），还是归档后仍可被随手编辑。
4. **过期产物被隔离吗**：工作区搜索是否把 archive 排除（`.rgignore`），防陈旧事实按词法命中挤掉当前结果。

**对照标杆**（dsh 实例，§2.3 / §7.3）：archived 169 篇 + append-only manifest（SHA-256 密封）+ `.rgignore` 隔离；rejected 10 篇全部集中在单一 class（其中绝大多数退场是"否决"而非"归档"）。

**打分刻度**：

| 水位 | 特征 |
|---|---|
| 0–2 | 无归档；过期决策要么消失要么堆积 |
| 3–5 | 有 archived 目录，但无冻结、无判据（靠字数按大小归档） |
| 6–8 | 冻结封印 + 语义判据到位，仅 `.rgignore` 隔离或 supersession 同 PR 缺失 |
| 9–10 | 全到位（冻结 + 隔离 + supersession 同 PR + deleted 也有判据） |

## 四问合成：怎么读这张表

- 单独看每问的 0–10，得到**四个维度的水位画像**。
- 交叉看找**瓶颈**：通常问②（强制）低会拖累其余三问——因为可验证性是一切约定生命力的放大器。优先投强制层。
- **分量表不替代细目库**：这里判"某个维度大概在哪档"，`checklist.md` 判"具体缺哪一条、命令是什么、最小改进动作是什么"。定档（S/M）由 `depth-selector.md` 的探测命令决定，不是靠分量表的主观印象。
