## 历史件豁免（不接 1.10 / 1.7 门禁）

实测（21 篇 `accepted/`）：**5 篇无 `## Alternatives considered`**、**1 篇无 `Status:` 行**（并集 6 篇），
其余 15 篇过这两轴；另有 20 篇的 `Status: accepted` 不在 1.7 的 `Status:` 词表
（`proposed` / `implemented` / `rejected — 理由`）里——旧轨道本就没有这套词表。

豁免口径：**历史件整批豁免**，不给本目录挂 ADR 判据（挂了即 6 篇恒红、20 篇 Status 不符）。

理由（停止线：**不改造历史**）：这些 Revision 的价值就是"框架规则当时怎么写的"的原文快照。为过今天的

是当时的原文），也抹掉"当时的契约要求长什么样"这一事实。**新决策按新契约写**：它们落在
`.agents/notes/`（同一真源、同一门禁），不受本豁免影响。

## 冻结的机械守卫（判定口径）

守卫是**只读报告**：只把"轨道被动过"报出来（`WARN`，**不改变任何退出码**），语义 = 新决策应写进
`.agents/notes/` 而不是本目录。形态与既有 `warn_governance_hygiene` / `warn_meta_violations` 同族：
只打印、不进审计命中数、不影响 exit。落点 = `ponygo audit` 的报告段（只读纪律允许 git 只读查询，
不执行仓库脚本）；**若该守卫尚未落地，本节即其验收口径**。**判定口径与落点无关**，只依赖 git 记录：

- **唯一判据**：`revisions/` 的最后一次变更必须不晚于**冻结提交** `cbc6f15`
  （"语料治理——退场机制首次实跑…"，本目录冻结与本节口径同批落地）。
- **观察面 = 已提交历史**：判据用 `git log`，工作区里"改了还没提交"的 `revisions/` 改动在提交前看不到
  ——这不是漏报，判据的观察面本来就是提交历史（守卫在每次提交后都复查一次）。
- 锚定命令：

```bash
last=$(git log -1 --format=%H -- revisions/)
git merge-base --is-ancestor "$last" cbc6f15 && echo PASS || echo WARN
```

**读法（WARN 不一律是违规，按改动面分档）**：

1. **只动了本文件**（`revisions/README.md`：冻结口径、豁免说明、悬空引用订正）→ 属"冻结边界的文档维护"，
   配一条 `.agents/notes/implemented/` 决策即可，不构成"重新开轨"。
2. **`accepted/` 或 `proposed/` 下新增或改写任何 `.md`** → 违反冻结：新决策改落 `.agents/notes/`，
   已落下的用 supersession 链回；唯一例外仍是上文第 2 条边界的"可机械验证的事实数字修正"
   （须同批在 `.agents/notes/` 侧有对应记录）。
3. **git 历史不可用**（无 `.git`、浅克隆缺历史、或 `cbc6f15` 不在历史中）→ 判定降级为 SKIPPED，
   **不得冒充 PASS**（"判不了"不写成"没动过"）。

**已知时点**：本节口径补充自身会让第 1 类 WARN 在本次提交后出现一次——这是守卫的预期行为
（它不区分"口径维护"与"新增决策"，只报"轨道被动了"），按读法第 1 条处置。
