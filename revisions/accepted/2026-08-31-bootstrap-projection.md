# Revision: 模板态投影初始引导（bootstrap）——治理指引前置到 AI agent 进场时刻（accepted）

Status: accepted

## 框架规则变更

`ponygo sync` 对槽位未填（模板态）的 constitution **不再拒绝投影**，改为投影一段
内置的**初始引导（bootstrap）**：受众是进入仓库的 AI coding agent，内容是五步
一次性引导——填宪法槽位（可推断的自己推断，不能的给草案注明待人确认）→ 重跑
`ponygo sync` → 照 write-adr 技能写第一篇 ADR 并把 level 改 1 → `ponygo status`
自证 L1 全绿 → 日常飞轮与升级路径索引。`ponygo init` 铺完骨架后**始终投影**
（模板态投引导，已填槽投命约）。引导写在投影标记区内，槽位填妥重跑 sync 时被
常载命约**整体替换，自动消失，无需手删**。

## 采纳理由（回馈证据）

ponygo 的目标场景是 AI coding 情境下的软件工程治理，但原设计里 TODO 守卫使
init 不投影——AI agent 进场时 AGENTS.md/CLAUDE.md 不存在，指引链在第一步就断了，
建治理体系的五步流程（填槽→sync→首篇 ADR→升 L1）只能靠"知道流程的人"手动执行，
而用户恰恰不知道这套流程。投影区是"每次会话必载"的唯一表面，引导必须长在那里。
标记区整体替换的既有机制使"引导退场"零成本——不需要第二条命令或人工删除。

## Alternatives considered

- **引导写进 constitution 模板正文（sync 原样投影）**：否决——模板态与实例态
  内容会漂移；引导与命约的生命周期不同（引导一次性、命约常驻），写进同一文件
  就要靠人记得删，正是被否决的"人工手动"方案。
- **CLI 加第七条命令（如 ponygo guide）**：否决——六命令面是拍板不变量；
  且 agent 不会主动跑一条它不知道的命令，指引必须长在常载表面。
- **保持 TODO 拒投影**：否决——见上，指引链在第一步断裂。

## 影响面

- 语义变化：模板态 init/sync 从"不投影"变为"投影引导"；`ai-surface: off` 仍然
  整体跳过（退场语义优先）。
- 宪法"停止线"第 1 条同步改写（模板态投引导非命约）；checklists/init.md 阶段 B
  从"人做"改为"agent 做、人确认草案"。
- 测试：s02/s04 改写为 bootstrap 语义（投影存在 → 填槽 → 引导被命约替换）。
