# Agent Note: 成熟度阶梯首版止步 L2，L3-L6 只给目标画像

Status: implemented

## Problem

成熟度模型常见的失败模式是：等级写得很满，判据却交付不了——声称"L5 负空间"，
但归档哈希封印、supersession 审计等机械验证脚本并不存在，等级沦为散文。

## Decision

L0-L6 七级中，**首版只交付 L0-L2 的可机械闭环**（每条判据锚定现成命令，
v1.1 起由 `ponygo status`/`audit` 逐项机械验证，不符 exit 1）。
L3-L6 在 maturity-ladder.md 中是"目标画像 + 依赖的未交付物清单"，
声称到达者必须同时掏出依赖的未交付机制，否则视为散文（P6 诚实条款）。
升级菜单式非线性（L3-L6 可勾选）、双向可退（retire 退级须录 decision）。

## Alternatives considered

- **首版冲 L3-L6 全判据**：否决——每级都需先交付一批带终身维护税的验证脚本，
  飞轮的起始条件是"转起来"而非"转得完美"。
- **L3-L6 写假门禁凑数**：否决——P6 形意分离，机器到不了的地方显式标"靠 review"，
  不写假门禁制造虚假安全感。
- **阶梯线性强制**：否决——不同项目类型的痛点顺序不同（monorepo 先要不变量，
  长命库先要归档），菜单式选装 + 按项目类型的推荐顺序表代替。

## Consequences

- "未交付物清单"（maturity-ladder §2）成为 L3-L6 解冻时的任务清单。
- L0 是合法长驻终态（纯 L0 长驻模式），停止线双向。
